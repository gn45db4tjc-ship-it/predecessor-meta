## 3. Findings, most consequential first

### F1. Phone Meta hides the "no hero is eligible yet" line on the first screen (high)
**Observed.** Phone Meta, Gold+, Jungle: 25 rows, every one "small sample" (3 to 49 games). No line says that no jungle hero has 100 games on 1.18. The engine does write that sentence ("No jungle hero has 100 or more games in Gold+ yet. Smaller samples remain visible below."), but in the default compact view it sits in `listStatus`, which compact mode shows only inside the `meta-context` disclosure, and that disclosure renders only when statistics are previous, unavailable or saved (`mobile.js` `guidedHome`, `unusual`). A current but ineligible sample is none of those, so the sentence never appears on the phone.

**Why it matters.** This is exactly the first days after a patch, when the phone is most likely to be opened to see "what's good now".

### F2. Rank numerals rank an alphabetical list (high)
**Observed.** With no tiers and no eligible rows, the "Tier" order falls back to name order: Akeron, Aurora, Bayle, Boris and so on. The CSS counter still draws 1, 2, 3 in the bright style on the first three rows (`broadcast.css` `#mobile-all-list>.mobile-hero-card::before`, and `.meta-table` on desktop). On the phone this reads as "Akeron is the best jungler" at 28.6% over 7 games. The desktop table does the same under an active "Tier ↑" header.

### F3. The hero page leads with a small-sample win rate and no qualifier (medium)
**Observed.** Phone Narbash support: "64.9%" in the large stat, "37 games · Pred.gg 1.18 · November 4" beneath it. Desktop Adele support: "54.5%" at plate size, "33 games · Pred.gg 1.18". Neither says "small sample" or "exploratory", although the Meta row for the same hero does (`companion_simple.js` `compactRoleText`; the desktop plate uses its own line).

### F4. The hero page doesn't show the official 1.18 changes for that hero (medium, highest value for "what changed")
**Observed.** Phone Steel support ends with a collapsed "Patch 1.17 · what changed for this hero · needs review", which is the reviewed 1.17 interpretation (`ui.js` `patchContextHTML`). The live guide holds official 1.18 hero changes for 17 heroes, Steel among them, and the engine already exposes them (`heroPatchChanges`). They appear only on phone Meta's favorites line and inside the compare fold, not on the hero page itself.

**Why it matters.** On patch week the most trustworthy thing the app can say about a hero is the official change text, shown as written. It needs no sample and no review, and it doesn't relabel old guidance as current.

### F5. Official 1.18 change counts differ between collections (verify, owner: recheck routine)
The 3 Nov recheck run recorded 157 hero changes over 37 heroes, 29 item, 21 perk and 64 unmapped from the official article. Today's Gold+ guide holds 64 hero rows over 17 heroes, 14 item, 4 perk and 37 unmapped. Some unmapped rows name loadout entries the queue tracks, such as Predator, which `plan-mechanics` items cite as "Loadout Predator". I haven't established the cause: the two runs may count differently, or the PC and cloud collectors may parse the article differently. It matters because F4 and `heroPatchChanges` read these rows. The recheck routine should confirm the parse before the 1.18 pass relies on it. This review doesn't change it.

### F6. Watchdog and runner doc still say "every 3 hours" (low, trust in status text)
Issue #191 says "Next attempt: the scheduled reviewer, every 3 hours (docs/RECHECK-RUNNER.md)". The routine has run daily at 20:32 UTC since 28 Oct (`watchdog.py` lines 222, 232, 245; `docs/RECHECK-RUNNER.md` line 5). Separately, issue #189 at 05:50 UTC still gave its next attempt as "a required-source retry at 2026-11-04 04:31 UTC", over an hour in the past, from manifest `required_retry.next_at`. A next-attempt time already in the past should say it is overdue.

### F7. Minor
- Desktop hero breadcrumb says "Meta · Gold+ · Jungle" on Adele support (it shows the Meta role, not the hero's).
- Desktop heading "Recommended build" sits over "Build recommendation unavailable".
- The phone "Current-patch build evidence is not available" callout is a filled tan box. The 2.55.0 rule is that a warning is an orange outlined chip, never filled yellow. It may be the neutral note style, but it reads as a warning; check against `docs/DESIGN-SYSTEM.md`.

## 4. Proposed plan

**Slice 1: "eligibility at the point of decision" (F1, F2, F3).** Recommended first. It doesn't overlap the recheck routine: it touches no review file, grade, plan or source, only how existing engine answers are shown.
1. Phone Meta: when the role has no eligible row, show the existing `availability` sentence as one visible `simple-source` line above the list in compact mode. Keep it to one line: a fact shared by every row is stated once at its head (2.50.0 rule).
2. Phone and desktop Meta: draw rank numerals only on rows ordered by a tier or an eligible rate. Rows in name order, or below the 100-game line, get no numeral. This is a CSS and markup change in shared styles, so agree it with the UI and design review thread.
3. Hero stat (phone and desktop): append "small sample" (phone) or "Exploratory" (desktop, matching the table) when games < 100. Use the same wording the Meta rows use.

**Slice 2: official changes on the hero page (F4).** Second. In the hero build area, a closed disclosure "Official 1.18 changes for Steel", listing `heroPatchChanges` rows as written, guide-gated, never labelled buff or nerf, with a link to the official article. It sits above or replaces the stale "Patch 1.17 · what changed" summary, and that summary keeps its "needs review" label. It should wait for F5's parse check.

**Hand-offs, not slices here.** F5 goes to the recheck routine's 1.18 pass. F6 is a small text fix in `watchdog.py` and `docs/RECHECK-RUNNER.md`, but the runner reads that doc as its instructions, so the owner of the routine should make it. F7 can join Slice 1 if it's cheap.

Implementation belongs in the existing improvements batch thread, per the project rule to batch related improvements, and needs the owner's go.
