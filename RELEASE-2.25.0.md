# Predecessor Meta 2.25.0 — The remaining audit repairs

This release finishes the repairs from the 2.23.0 audit. It follows 2.24.0 and, like it, adds no features and removes none. Saved selections, all six brackets, reviewed guidance, source rates, samples and dates are unchanged. No number is estimated, no bracket is substituted, and no review status or review date is changed by this release.

## What changed

**One failed hero page no longer discards a fresh collection.** Previously a single Statz hero page that failed to load threw away the whole day's collection for that rank. Now a collection publishes when at most 10% of its hero pages failed (the collector's existing warning threshold). The roles that were collected publish with their own numbers. A role whose hero page failed keeps no hero-page statistics (role win rate, builds, matchups), is listed in the manifest, and is never filled in from another source or another day; its separately collected tier-list row is still shown as collected. The gap is stated in the evidence state, the desktop source note and the phone status line. It is also treated as a required-source failure: it is named in the collection record, retried at most twice three hours apart, and reported by the workflow, whether or not Pred.gg is also unavailable. A page that reports a different patch is still an absolute reject, so patches can never blend, and the page counts must reconcile exactly; a page that downloaded but could not be read counts as failed. The last complete collection is kept untouched alongside.

**Saved offline ranks survive every release, and only verified data is saved.** The app used one cache, named after the release, for both the page and your saved ranks. Every new release deleted the saved ranks, and the background worker stored any response with status 200 before the page had checked it, so a hotel or airport sign-in page could replace a verified rank. There are now two caches: a release shell, and a permanent data cache that no release deletes. Only the page writes to the data cache, and only after a bundle passes its checksum and structure checks. It saves the new bundle first, then a manifest that describes exactly what is saved (each rank with its own checksum and dates), and only then removes that rank's older bundle. Saving happens after the page has already switched to the new data, so it never delays what you see, and the page never shows one publication while ranking from another; an update check counts as complete only once the offline copy is saved. Open tabs take turns saving, and before the saved manifest is used offline it is checked against what is actually saved. Ranks saved by 2.23 or 2.24 are moved across once on upgrade, each verified against the checksum in its own name. A saved rank whose patch signature cannot be established is treated as possibly out of date, never as current. A full-storage device gets an explanation and keeps working online. If the website is ever rolled back to 2.24 or earlier, that release removes the new caches and starts saving afresh, rather than serving a frozen copy.

**Five-hero composition search no longer freezes the page.** The search now runs in a background worker built from the engine code already in the page, on the website and, with your approval, in the Windows app. The button shows progress. A result that finishes after your picks, bans, enemies or data changed is discarded, and the page says why; alternatives that are already current on screen are kept. Where a worker cannot start (saved-file exports do not allow one), the same search runs exactly as before. The recommendations are byte-identical either way, including with bans, enemy picks, a required role and unsampled heroes; this is enforced by tests.

**Strategy review packets now carry the official changes, and the cloud queues them for you.** The downloadable packet read a field that does not exist and exported zero official changes. It is now built by one engine function and contains the official and hotfix changes, every reviewed plan with the changes that touch its hero, items, crest, augment, Eternal or blessings, definition conflicts, the evidence state, and the checksum and dates of every published rank. A change is flagged for a plan only when its patch number is later than the patch the plan was reviewed for (1.16.10 is later than 1.16.9); a patch number that cannot be ordered is flagged for a person to check, and a plan whose result is unresolved is always flagged. The cloud publishes a small review queue (`review/index.json` plus the newest eight packets). A new packet appears at once for a new patch, a hotfix on any live official article (including the preceding launch article, where hotfixes are usually posted), a new human review, or when the guidance says it needs review; otherwise one appears on Sundays after that day's collection, so it references the bundles then published. Preparing a packet is read-only. It never changes a review status, a review date or a recommendation; approving strategy remains a human decision.

**Cloud collection is primary; this PC is manual recovery.** Each collected rank now records who actually collected it (the cloud run and its id, this PC, or a local run), and the manifest reports that per rank instead of inferring it from configuration. When a collection keeps (retains) sources from an earlier one, the record also names who collected each kept part (Statz and Pred.gg separately), taken from the kept data itself. Data collected before this release is reported as unrecorded, never guessed. An upload from this PC is imported only when genuinely newer: a later assembly of older sources never replaces the publication, and this applies to every dated source, Pred.gg included. Only published sources that actually hold data are compared, so a source that failed in the published copy never blocks a recovery. A refused upload leaves the cloud's own collection record and schedule untouched, and an upload can never label itself as a cloud run. The Windows updater installer now creates only the Desktop recovery shortcut and removes the sign-in shortcut older versions created.

## Independent review

Before publication, every phase was reviewed by an independent reviewer, and each finding was then challenged by a second reviewer who tried to disprove it against the code. Of the 35 findings that held up across 2.24.0 and 2.25.0, 20 concern this release's code; all 20 are fixed here, and 3 further findings whose challenge could not complete (the review run was cut short) were fixed as well. Each fix has a test that fails on the code before it. They cover: the page showing one publication while ranking from another when two update checks overlapped a slow save; offline copies after a website rollback; two tabs saving at once; a late worker result discarding a current result; worker tests that did not exercise bans or enemies; a tolerated page gap that was silently accepted when Pred.gg was also down; page counts that did not reconcile when a page could not be read; review packets that missed later hotfixes and flagged earlier articles; a hotfix on the launch article not queuing a packet; the weekly packet being built before that day's collection; a status revision written as a checksum; Pred.gg dates that could move backwards through an upload; refused uploads overwriting the cloud's schedule; retained sources losing their collector; and three tests that could not fail. One further fix came from combining the two releases: a current Pred.gg update is not limited by the fresh-Statz 10% page rule.

A third review of the combined releases confirmed 5 more findings in this release's code, all fixed with tests that fail on the previous code: a finished search could redraw the page while you typed elsewhere (it now waits like every other automatic redraw and keeps your cursor); an offline copy re-described from what is saved could borrow the newest publication's statistics date; a failed offline save was not retried until the next new publication; a source that failed in the published copy could block a manual recovery; and the record of who collected retained sources was copied from the previous publication instead of from the kept data.

## Verification (actual results, 18 September 2026, Windows 11, Python 3.12.10, Node 24.19, Edge 153)

- Python: 178 tests, all pass, 1 skipped where no local bundle store exists. (2.24.0: 143; 2.23.0: 97.)
- JavaScript: 149 tests, all pass. (2.24.0: 101; 2.23.0: 78.)
- Audit browser suite on the staged build: 39 of 39 verdicts match the ledger, and the ledger of open defects is empty. Longest main-thread stall while generating five-hero alternatives: 31 to 52 ms across runs (40 ms in the final run; 2.23.0: 1,398 ms; budget 500 ms).
- Offline cache suite, real service worker in a real browser, 7 of 7: only verified data saved; all six ranks saved; a captive-portal page served as a newer bundle never replaces a saved rank; a next release keeps all six; restart with the network down opens all six with their original dates; a legacy cache is moved on upgrade; and an upgrade from a cache written by the actual 2.23.0 worker opens all six ranks offline afterwards. Sandbox tests add the rollback to the 2.23/2.24 worker and the re-described saved manifest.
- The two older suites that failed identically on 2.23.0, `browser_ranks.cjs` and `browser_static.cjs`, now pass: their outdated expectations were updated (test files only).
- `browser_release_222`, `browser_companion_accessibility` (axe WCAG 2.1 A/AA, both themes, no violations) and `browser_companion` (six brackets, no page errors) pass on the staged build.
- A synthetic "one hero page failed" publication was staged end to end and opened on desktop and phone: the failed role shows no hero-page statistics, collected roles are unchanged, the gap is stated, no page errors.
- Clean-room source package (89 files, unpacked into an empty folder and tested there): 178 Python tests run with 6 skipped, and 146 JavaScript tests pass with 3 skipped. The skips are the checks that need the public seed or the local bundle store, which are not part of the package.
- The Windows app, started from an isolated data folder, ran the five-hero search in the worker with results identical to the main-thread search.

## Known gaps

- Not tested on a physical phone, with VoiceOver or TalkBack, or as a natively installed app. The offline upgrade was verified in desktop Edge with the real service worker, not on iOS Safari, whose storage eviction rules differ.
- A tab or installed window that was already open when 2.25.0 arrived keeps running the old page code until it is reloaded. While it stays open it saves nothing new for offline use, and if the network drops it may fall back to the older saved copy. Dates stay truthful, and reloading once (or closing and reopening the app) fixes it.
- The worker holds a second copy of the loaded rank's data while it exists. It is created only when you first generate alternatives. Memory on older phones was not measured.
- An upload from this PC is refused when any of its sources, Pred.gg included, is older than what is published. If the cloud has a newer Pred.gg sample than this PC, a manual recovery of Statz from this PC is refused with a message naming the source, rather than moving that date backwards.
- The cloud review queue and collector records are verified locally and in tests. They are only proven in production once a real cloud run publishes them.
- Retiring the old copy of the publishing key and enabling branch protection are intentionally not done yet. They wait for two consecutive verified cloud receipts and one verified manual recovery run from this PC.
- The suites were last certified on Edge 152; these runs used Edge 153.

## Rollback

Windows app: quit the app, then run **Roll Back 2.25.0.bat**. It verifies the backup's checksums before restoring the previous version and does not touch `data\`, `snapshots\` or `settings.json`. Website: revert the 2.25.0 merge commit on `main`; Pages redeploys the previous release. After a website rollback, the previous release's worker removes this release's caches on its first visit and saves ranks afresh as they are opened online; nothing it shows comes from a frozen copy. Never force-push and never reset the `data-updates` branch.
